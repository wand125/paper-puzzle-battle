# hibverify — 独立結果検証器

Rust 2021 / 標準ライブラリのみで実装しています。`rust/` のコードや依存関係は使用しません。盤面の幾何情報や対称性による正規化も使用しません。

## ビルド・テスト

この `verify/` ディレクトリで実行します。

```sh
cargo build --release --offline -j 2
RUST_TEST_THREADS=2 cargo test --release -j 2
./target/release/hibverify play normal 14,18,0,60
```

データはコンパイル時の本クレート位置を基準とした `../web/data/solutions.bin` から読みます。8 バイト × 1,304,983 件であることと、盤面外のビットがないことを検査します。実行時にもこのデータファイルが必要です。

## 使用方法

```sh
./target/release/hibverify solve normal jobs.txt results.txt 2
./target/release/hibverify solve pass jobs.txt pass-results.txt 2
./target/release/hibverify play pass 14,37,15
./target/release/hibverify play normal -
```

ジョブファイルは 1 行につき `key stones`。キーは空白を含まない任意の文字列、石は `14,37,15` のようなセル番号の列です。空の配置には `-` を指定します。セル番号は 0〜60、重複した石や解が残らない配置はエラーです。入力した配置までの着手履歴の合法性は検査しません。

結果は `key value nodes ms n` の形式で追記し、行ごとに flush します。`value` は手番側の勝ちが 1、負けが 0、`n` は残る解の数です。`ms` はジョブの絞り込み・ビット列構築・探索にかかったミリ秒です。同じ結果ファイルに存在するキーは次回スキップします。結果ファイルはルール・データ・ジョブの対応を変えずに再使用してください。並列実行では完了順に出力します。

30 秒ごとに標準エラーへ経過時間、完了数 / 全ジョブ数、実行中の各キー・経過秒・ノード数を表示します。ノード数は終端を除く探索呼び出し数で、置換表によるヒットも含みます。実行中の表示は約 1,024 ノード間隔で更新します。

## 探索の設計

各ジョブの解を局所的に番号付けし、61 セルそれぞれのビット列を構築します。子局面は列との AND を取り、非ゼロの `(ワード番号, ビット列)` だけを保持します。popcount で着手先の解数を計算し、解数の小さい手から厳密な勝敗探索を行います。解数 1 への手は即勝ちです。解数 2 への手は次の相手に即勝ちの手があるため省略できます。

確定黒 `D` は残る解の AND で求めます。NORMAL の置換表キーは `D`、PASS は `(D, p)`。PASS の通常手では `p + |D'| - |D| - 1`、パスでは `p - 1` に更新します。残り解数が 1 以下なら、パス数に関係なく手番側の負けです。

各ワーカーは独立した置換表を持ち、同じデータに対するジョブ間で再使用します。既定の上限は各ワーカー 3,000 万件で、上限到達時に内容をクリアします。メモリの余裕に応じて環境変数で調整できます。0 は表を無効化します。

```sh
HIBV_TT_MAX=1000000 ./target/release/hibverify solve pass jobs.txt results.txt 2
```

テストでは固定シードの自作乱数で初期局面から合法な 6〜10 手を生成し、残り解数 20〜400 の異なる局面を両ルールそれぞれ 200 件検査します。比較対象は明示的な解リストを使う素朴な再帰探索で、置換表や解数 2 の省略を使いません。参照実装も子の解数順に列挙しますが、合法な子を省略せず、パス数は置かれた石の総数から毎回求めます。指定された既知局面 `14,18,0,60` の 3,136 解・NORMAL 勝ちも検査します。
